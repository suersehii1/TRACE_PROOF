# TraceProof 기능 사용 설명서

## 제품이 돕는 업무

장비 소프트웨어나 설정이 바뀐 뒤 제공 데이터가 승인 기준과 맞는지 대조합니다. 원본 데이터, 검사 기준, 판정, 담당자 검토가 함께 남습니다. 자동 원인 확정이나 고객 인수 승인 도구는 아닙니다.

## 접속과 화면

기본 주소는 `http://localhost:8088`입니다. PC에서는 왼쪽 메뉴, 휴대폰에서는 아래 메뉴를 사용합니다. 장비 연결 여부와 동기화 시각은 화면 위·아래에서 확인할 수 있습니다.

| 메뉴 | 하는 일 |
|---|---|
| 변경 검증 | 기준과 수정 버전 선택, 비교, 원본 근거, 담당자 검토 |
| 장비 데이터 | 모의 장비 전송, JSON 파일 업로드, 원본 다운로드, 승인 항목표 보기 |
| 검증 이력 | 기존 검증 다시 열기, 현재 검토 상태, 보고서 열기 |
| 사용 가이드 | 앱 안에서 5분 시연과 판정 설명 확인 |

## 1 데이터 등록

최초 시작 시 모의 장비가 기준·결함·정상 수정 자료를 자동 전송합니다. 자료가 없으면 새로고침하고, 장비 데이터 메뉴의 시나리오에서 필요한 버전을 골라 **장비에서 전송**을 누릅니다.

직접 올리려면 **JSON 파일 업로드**를 누르고 RAW_DATA의 파일을 선택합니다. UTF-8 JSON, 5MB 이하, 20,000표본 이하만 지원합니다. 등록되지 않은 장비 ID나 잘못된 형식은 오류로 안내합니다. 오류 파일은 정상 자료로 저장하지 않습니다.

동일 원본은 SHA-256으로 중복 확인하여 기존 자료를 선택합니다. 같은 파일 이름이 아니라 내용 바이트를 비교합니다. 새 자료를 등록해도 예전 검증의 원본과 결과를 덮어쓰지 않습니다.

## 2 변경 검증 실행

변경 검증에서 **기준 데이터**와 **비교 데이터**를 선택하고 **검증 실행**을 누릅니다. 같은 자료를 양쪽에 선택할 수 없으며 장비·운전 시나리오가 다르면 API에서 거부합니다.

기준 데이터도 같은 기준표로 검사합니다. 기준에 문제가 있으면 수정 데이터가 좋아도 승인할 수 없습니다. 기준과 수정 버전의 조건이 실제로 같은지 담당자가 확인해야 합니다.

| 검사 | 의미 |
|---|---|
| 시험 결과 버전 | 시험 증거의 SW 버전과 해당 자료의 SW 버전 일치 |
| 필수 표본 | 승인 항목이 존재하고 최소 표본 수 충족 |
| 단위 | 모든 표본의 단위가 기준표와 일치 |
| 값과 범위 | 유효 수치이고 허용 범위를 만족. 단위가 다르면 유보 |
| 시각과 간격 | 시차 포함 시각, 원래 수신 순서의 간격·중복·역전 확인 |
| 작업 번호·챔버 | 기준표에서 허용한 작업과 공정 공간에 연결 |
| 추가 항목 | 기준표에 없는 수신 항목은 확인 대상으로 표시 |

**통과**는 기준 만족, **실패**는 위반 확인, **판단불가**는 근거 부족, **미실시**는 자료·설정이 없어 검사하지 않은 상태입니다. 합계는 검사 행의 수이며 센서 수나 불량률이 아닙니다. 미실시와 판단불가도 전체 분모에 포함됩니다.

데모 정상 버전은 31개 검사 중 통과 30개, 미실시 1개입니다. 미실시 1개는 진동 범위가 지정되지 않은 비필수 검사입니다. 필수 미실시·실패·판단불가는 승인을 막습니다.

## 3 원본과 추이 확인

결과 카드 또는 필터에서 실패·판단불가만 볼 수 있고 항목 ID·검사·관측 결과를 검색할 수 있습니다. **원본 확인**을 누르면 기대 기준·관측 결과·해당 JSON 행을 확인합니다.

행 번호는 원본 JSON의 measurements 배열에서 **1부터 시작하는 순서**입니다. 관련 표본이 없거나 manifest 검사일 때는 원본의 버전 정보가 표시됩니다. 원본 JSON을 내려받아 전체 기록도 확인할 수 있습니다.

추이 그래프의 가로축은 시각이 아닌 **표본 순서**입니다. 시간 간격 오류는 시각 검사에서 확인합니다. 기준과 수정 데이터의 단위가 다르면 오해를 막기 위해 두 그래프를 겹쳐 그리지 않습니다.

SHA-256은 수신 후 파일 변경 여부를 확인하는 해시입니다. 센서가 물리적으로 정확하거나 원본 기록이 사실이라는 인증은 아닙니다.

## 4 검토와 승인

검토자와 의견을 입력한 뒤 **보류 기록** 또는 **검토 승인**을 누릅니다. 보류는 결함 후속 조치를 기록하는 용도입니다. 필수 문제가 남아 있으면 승인 버튼이 비활성화되고 API도 승인을 거부합니다.

오류를 수정한 파일을 새로 올리고 **새 검증**을 실행해야 이전 판정을 바꿀 수 있습니다. 검토 의견은 추가 이력으로 저장하며 기존 기록을 수정·삭제하는 화면은 없습니다. 정상 결과를 검토 승인했더라도 필요하면 보류 기록을 추가할 수 있습니다.

검토자 이름은 MVP에서 직접 입력하는 표시 값입니다. 로그인 사용자 인증·전자서명은 아니며 운영 도입 시 계정·역할·승인 권한 연동이 필요합니다.

## 5 보고서와 저장

**보고서 열기**는 현재 저장된 판정·기준 스냅샷·검토 이력을 새 창에 표시합니다. 브라우저 인쇄에서 PDF 저장을 선택하면 공유용 파일을 만들 수 있습니다. 보고서 파일 자체를 서버가 자동 PDF로 변환하지는 않습니다.

CSV 저장은 검사 상세를 Excel에서 볼 때 사용합니다. 한국어 인식을 위한 UTF-8 BOM이 포함됩니다. JSON 원본 다운로드도 가능합니다. 각 보고서는 생성 시점에 저장된 검토 상태를 보여 주므로 이후 상태 변경 후 다시 열면 검토 이력이 추가됩니다. PDF로 저장한 파일은 저장 당시의 내용입니다.

## 6 휴대폰 사용

같은 Wi-Fi/LAN의 `http://PC의IPv4:8088`로 접속합니다. 메뉴는 아래에 있으며 긴 표는 표 안에서 좌우로 스크롤합니다. 원본 확인 창은 닫기 버튼으로 닫습니다. 휴대폰 인쇄·PDF 기능은 브라우저 지원에 따릅니다.

## 문제가 있을 때

| 현상 | 확인 |
|---|---|
| 화면이 안 열림 | Docker Desktop 실행, `docker compose -p traceproof_mvp ps`, 8088 포트 충돌 |
| 데이터가 없음 | simulator 상태, 장비 전송, 새로고침 |
| 장비 전송 실패 | backend/simulator의 DEVICE_TOKEN 일치와 로그 |
| 형식 오류 | RAW_DATA 예제와 manifest·measurements 형식 비교 |
| 승인 불가 | 기준 데이터 문제·필수 실패·판단불가·미실시 확인 |
| 그래프가 안 겹쳐짐 | 단위 불일치 경고 여부 확인 |
| 휴대폰만 접속 불가 | 같은 네트워크, PC IPv4, 개인 방화벽 정책 |

앱의 초기 데모 비밀번호·장비 토큰은 예제 값입니다. 로그인·사용자별 권한·TLS·다중 고객 격리가 없는 시연용이므로 실제 고객 원본이나 인터넷 공개 운영에는 별도 보완이 필요합니다.
